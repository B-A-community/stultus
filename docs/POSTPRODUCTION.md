# Постпродакшн выбранного ракурса

## Сценарий

1. Пользователь выставляет ракурс в SketchUp и пишет: «Сделай визуализацию этого вида: мягкий вечерний свет, натуральные материалы».
2. Агент вызывает `render_viewport({prompt})`. Он не переставляет камеру и не правит модель.
3. В Graphite появляется карточка с описанием и кнопками «Зафиксировать и создать», «Изменить», «Отмена». «Изменить» открывает задание в поле прямо в карточке — на генерацию уходит текст пользователя, и агент об этом узнаёт из ответа инструмента. Отмена не запускает генератор.
4. После подтверждения Ruby сохраняет framebuffer вьюпорта в PNG. Размеры берутся из самого PNG, без подгонки к 1280×800. Камера, режим перспективы, выделение и геометрия не меняются.
5. Gateway передаёт изображение отдельному процессу `codex app-server`. Встроенный генератор получает ограничения: сохранить ракурс, кадрирование и архитектуру, улучшить свет и материалы.
6. Готовый кадр отображается в чате. «Исходник / Результат» переключает изображения, клик по картинке раскрывает её на всё окно (клик или Esc — закрыть), «Сохранить PNG» открывает диалог сохранения.

Генерация может отклониться от исходной геометрии. Функция создаёт презентационный кадр, не точный физический рендер. При несовпадении формата результата агент получает предупреждение.

## Подключение

Нужен Codex CLI со встроенной image generation и выполненный вход ChatGPT под пользователем gateway. На проверенной виртуалке CLI находится в `/opt/stultus/app/server/node_modules/.bin/codex` (0.154.0), вход выполнен под `maksar` через файловый кэш с правами `600`.

```bash
/opt/stultus/app/server/node_modules/.bin/codex login --device-auth
/opt/stultus/app/server/node_modules/.bin/codex login status
```

После входа добавить `RENDER_ENABLED=1` в окружение gateway. `CODEX_HOME` должен указывать на каталог с этим входом. При использовании системного хранилища входа вместо `auth.json` проверку готовности нужно расширить; текущая реализация ожидает файловый auth cache, типичный для Linux-сервера.

Можно задать `RENDER_CODEX_PATH`, `RENDER_MODEL` (модель агента; по умолчанию `CODEX_DEFAULT_MODEL`) и `RENDER_TIMEOUT_MS`. Генерация использует лимиты Codex. Для этой реализации отдельный Images API key не нужен. Она не извлекает токены для обращения к неофициальным endpoint.

Обновить сервер и плагин вместе. На сервере — `npm ci`, `npm test`, `npm run build` и перезапуск сервиса. Плагин — штатный `dev_install.ps1` и перезапуск SketchUp. При горячей подгрузке нужно загрузить новый `render_assets.rb`, обновлённые `screenshot.rb` и `dialog.rb`, затем переоткрыть окно.

## Технические детали

- Новый MCP-инструмент: `render_viewport`, аргумент `prompt` до 6000 символов.
- Окно возвращает `tool_result` с исходным PNG и `capture: {framing:'viewport',width,height}` только после подтверждения.
- Gateway присылает `render_status` и `render_result` с id, исходником и результатом.
- Native app-server протокол: `initialize`, `thread/start`, `turn/start`, `item/completed` с `imageGeneration`, `turn/completed`.
- Отдельный временный каталог для каждого кадра; исходник удаляется после завершения. Чужие MCP-серверы, shell, apps и web для генератора отключены. На проверенной VM файловая песочница `bubblewrap` не может настроить loopback и блокирует даже чтение входного PNG, поэтому короткоживущий image-worker запускается без неё; доступные ему инструменты при этом ограничены встроенной генерацией изображения. Штатные изображения самого Codex могут остаться в его каталоге `generated_images`.
- Отмена прерывает ожидание снимка и процесс генерации; поздний ответ не принимается. Отмена не гарантирует возврат уже использованных лимитов сервиса.
- Повтор хода после ошибки продолжения сессии запрещён, если агент уже выдал ответ или вызвал инструмент: дорогостоящая генерация не должна повторяться автоматически.
- PNG результата и исходника сохраняются локально в `%LOCALAPPDATA%/Stultus/renders`. В `.skp` записывается только id кадра и текст задания. При переносе `.skp` на другой компьютер прежние картинки могут быть недоступны — их нужно экспортировать отдельно.
- Предел одной картинки — 24 МиБ; при проблеме сохранения интерфейс показывает ошибку.

## Проверки и статус

Проверено: TypeScript typecheck и build; 7 серверных тестов (нативные события на имитаторе, ошибка лимитов, отсутствие картинки, отмена, валидация PNG, ограничения промпта, поздний ответ после отмены); браузерные проверки подтверждения, сравнения, экспорта, истории без base64, восстановления, размеров 380/700/1200, отмены.

На живом SketchUp `tests/live_viewport_capture.rb` получил PNG 1615×883 при вьюпорте 1615×883. Состояние камеры, выделения и список сущностей до и после совпали. Это проверка текущей сцены; отдельный прогон на двухточечной перспективе и других проекциях ещё нужен.

Сквозная генерация проверена на виртуалке настоящим `codex app-server` 0.154.0 с входом ChatGPT: из живого кадра SketchUp 1615×883 получен PNG 1696×927. Тест выявил и закрыл различие протокола: уведомления `item/completed` и `turn/completed` могут приходить без `threadId`. Результат сохранил выставленный ракурс, шесть панелей, синюю третью панель, тестовую геометрию слева и масштабную фигуру.
