# Stultus — техническое приложение к дизайну (для верстальщика)

Это не ТЗ на дизайн (оно в [DESIGN-BRIEF.md](DESIGN-BRIEF.md)), а
описание того, за что держится JS окна. Дизайн заменяет
`src/stultus/html/app.css` и при необходимости разметку `index.html`;
имена классов, id и data-атрибутов ниже должны сохраниться либо JS
правится вместе с ними.

## 1. Где живёт окно и чем ограничено

- Окно — `UI::HtmlDialog` SketchUp 2024, движок Chromium (CEF ~112).
  Современный CSS (grid, flex, custom properties, `:has`, container queries)
  работает. Внешних ресурсов нет: шрифты, иконки — только локальные файлы
  внутри плагина или системные. Ссылки на CDN не загрузятся.
- Окно **отдельное от SketchUp, свободно перетаскивается и меняет размер**.
  У всех сотрудников два монитора: окно часто уносят на второй и разворачивают
  на всю высоту, а то и на всю ширину. Размер запоминается между сеансами.
- Минимальный размер 380×460, стартовый 520×760, верхнего предела нет.
  Дизайн обязан работать в трёх режимах:
  - **узкий** (380–600 px) — панель у края экрана рядом с моделью;
  - **обычный** (600–900 px);
  - **широкий** (900+ px, второй монитор) — лента не должна растягиваться
    в строки по 300 символов: ограничить ширину читаемого столбца, свободное
    место отдать под код и снимки.
- Темы: у SketchUp 2024 на Windows светлый интерфейс. Основная тема —
  **тёмная** (окно ИИ рядом с белым вьюпортом меньше режет глаз, это
  подтверждено на пилоте), но токены цвета вынесены в `:root`, светлая тема
  приветствуется как вторая, переключение — атрибут `data-theme` на `#app`.
- Плотность: это рабочий инструмент, а не мессенджер. Базовый кегль 13 px,
  межстрочный 1.45, отступы компактные. Шрифт: системный (`Segoe UI`) плюс
  моноширинный для кода (`Cascadia Mono` / `Consolas`).

## 2. Кто пользуется и как

Архитектор/визуализатор в SketchUp. Сценарий: пишет задание («сделай лестницу
из этого проёма на второй этаж, ширина 1000»), смотрит, как модель по шагам
исполняет код и что получилось, отвечает на вопросы, разрешает или
запрещает снимок вьюпорта, при неудаче жмёт «Стоп» и откатывает Ctrl+Z в
SketchUp. Переписка привязана к файлу модели и восстанавливается при
следующем открытии.

Важно для дизайна:

1. **Ход модели — это последовательность «текст → вызов инструмента →
   текст»**, и порядок должен читаться. Вызовы инструментов — компактные
   свёрнутые карточки между пузырями текста, а не отдельные сообщения.
2. **Состояние соединения и занятости всегда видно**: не подключено /
   подключаемся / подключено / модель работает. Пока идёт ход, поле ввода
   заблокировано, есть кнопка «Стоп».
3. **Просьба о снимке — заметная карточка с двумя кнопками**. Это единственное
   место, где пользователь обязан среагировать во время хода. Нельзя, чтобы она
   терялась среди карточек инструментов.
4. **Вопрос модели** — карточка с вариантами-кнопками; нажатие отправляет
   вариант как сообщение пользователя.
5. **Ошибки инструмента** должны быть видны без раскрытия карточки (индикатор
   состояния), а раскрытая карточка показывает код и текст ошибки моноширинным.
6. Расход токенов и стоимость хода — мелкой строкой под полем ввода, не в
   ленте.

## 3. Структура экрана (DOM-контракт)

Корень `#app.app` с `data-state` ∈ `disconnected | connecting | connected | busy`.

```
header.topbar
  .topbar__title   → .topbar__name «Stultus», .topbar__model (#modelTitle — имя файла модели)
  .topbar__status  (#connStatus) → .dot + .topbar__statusText
  .topbar__actions → button.iconbtn#btnNew, button.iconbtn#btnSettings

section.provider
  label.provider__field → select#providerSelect   (Claude / Codex; ненастроенные — disabled)
  label.provider__field → select#modelSelect
  label.provider__toggle → input#attachScene (чекбокс «сцена в запросе»)

main.chat#chat                       ← прокручиваемая лента
  .chat__empty#chatEmpty             ← пустое состояние (два абзаца)
  article.msg.msg--user | .msg--assistant | .msg--system | .msg--error
     .msg__role, .msg__body           (.msg--assistant.is-streaming — печатается)
  details.tool[data-state=running|ok|error]
     summary.tool__summary → .tool__icon .tool__name .tool__label .tool__state
     pre.tool__args, pre.tool__result
  .card.card--ask   → .card__title .card__text .card__options(button.btn…)
  .card.card--shot  → .card__title .card__text .card__options(button[data-act=allow], button[data-act=deny]) img.card__preview
     (.card.is-done — решение принято, кнопки скрыты)

footer.composer
  .composer__hint#composerHint       ← предупреждения («нет связи…»), пусто = скрыт
  .composer__row → textarea#input, .composer__buttons → button#btnSend, button#btnCancel[hidden]
  .composer__meta → span#usage

aside.settings#settings[hidden]      ← оверлей настроек
  .settings__panel → h2, label>input#setGateway, label>input#setToken, p.muted,
                     .settings__buttons(#btnSaveSettings, #btnCloseSettings), hr,
                     button#btnClearHistory, p#settingsInfo
```

Шаблоны `<template id="tplMessage|tplTool|tplAsk|tplShot">` в конце
`index.html` — клонируются JS. Менять внутреннюю разметку шаблонов можно,
если сохранены классы, по которым JS пишет содержимое (перечислены выше).

Тело сообщения модели (`.msg__body`) — HTML из мини-markdown: `<p>`, `<ul>`,
`<strong>`, `<code>`, `<pre><code>`. Нужны стили для всех пяти.

## 4. Состояния, которые надо нарисовать

| Элемент | Состояния |
|---|---|
| Шапка / точка статуса | disconnected (красный), connecting (жёлтый), connected (зелёный), busy (акцент, можно пульс) |
| Сообщение модели | печатается (курсор), готово |
| Карточка инструмента | running / ok / error; свёрнута / раскрыта; `execute_ruby` показывает код, `get_scene` — JSON |
| Карточка снимка | ожидает решения; сделан (превью картинки внутри); отказано |
| Карточка вопроса | ожидает; ответ выбран |
| Композер | обычный; ход идёт (textarea disabled, «Стоп» вместо «Отправить»); подсказка-предупреждение |
| Провайдер | настроен / не настроен (disabled в select) |
| Пустая лента | первое открытие |
| Настройки | оверлей поверх всего; поле пропуска — password |

## 5. Что нельзя

- Нельзя менять id/классы из раздела 3 и порядок `#btnSend`/`#btnCancel`.
- Нельзя грузить шрифты и иконки по сети. Иконки — inline SVG или файлы в
  `src/stultus/icons/`.
- Нельзя делать высоту ленты фиксированной: она занимает всё между шапкой и
  композером при любом размере окна; горизонтальной прокрутки страницы быть
  не должно (код прокручивается внутри `pre`).
- Не полагаться на hover как на единственный способ показать состояние —
  часть сотрудников работает с планшетом.

## 6. Что сдать

- `app.css` целиком (можно с `@import` локальных файлов) + при необходимости
  изменённый `index.html`;
- иконки: панель инструментов SketchUp 16/24/32 px (`stultus.png` или svg),
  иконки кнопок шапки, точки состояния, индикаторы карточек;
- макеты трёх ширин (380 / 700 / 1200 px) в тёмной теме, светлая — по
  желанию;
- перечень токенов (`:root`) с назначением.

Проверка: `dev_install.ps1`, открыть Extensions → Stultus в SketchUp 2024,
пройти сценарий из раздела 2 против тестового gateway (адрес и пропуск даст
разработчик).
