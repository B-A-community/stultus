# Журнал изменений

Формат: что изменилось и почему. Версия расширения задаётся в
`src/stultus/constants.rb`, оттуда же её берёт сборщик пакета.

## 0.1.0 — тестовая сборка

**Релиза нет, пакет для установки не выкладывается.** Собирается локально
(`tools\build_rbz.ps1`) под именем `Stultus-0.1.0.rbz` и раздаётся напрямую
на время проверки.

Первая версия.

### Плагин

- Окно чата на `UI::HtmlDialog`: провайдер и модель, лента с пузырями текста
  и свёрнутыми карточками инструментов, карточки вопроса и просьбы о снимке,
  стриминг ответа, кнопка «Стоп», настройки адреса gateway и пропуска.
- Сеть — в JS окна (WebSocket к gateway), Ruby — только инструменты:
  `execute_ruby` (одна операция Undo, откат при ошибке, перехват stdout,
  обрезка результата), снимок сцены, снимок вьюпорта с временной сменой
  ракурса, undo.
- Переписка и идентификаторы сессий провайдеров — в словаре атрибутов
  модели `BACommunity_Stultus`, лимит 150 КБ, без картинок, прозрачной
  операцией.
- Настройки — через `Sketchup.write_default`, в файл модели не попадают.

### Выделение (2026-09-12)

- Наблюдатель выделения: строка под полем ввода показывает, что выделено,
  и уходит с каждым сообщением первой строкой промпта.
- Описание выделенного: грани (площадь, нормаль, хозяин), рёбра (длина),
  экземпляры компонентов (сколько всего у определения) — с предупреждением
  про make_unique, если выделены не все.
- Инструмент `select`: модель выделяет объекты по id и наводит камеру.
- Проверено вживую: одно окно из шести — меняется одно (make_unique), пять
  выделенных — меняются пять через определение, пусто — модель спрашивает.
- Исправлен порядок осей в габаритах (`BoundingBox#height` — Y, `#depth` — Z).

### Лимиты, Undo, сцены, копилка, тема (2026-09-15)

- Лимит времени на `execute_ruby` (90 с, настройка `ruby_timeout`;
  **может вызывать нестабильность и вылеты** при прерывании посреди вызова
  API — см. USER-GUIDE).
- Один ход модели — один пункт Undo (прозрачные операции).
- Инструмент `scenes`: список, переход, сохранить вид сценой, обновить,
  удалить. Пакетный рендер = сцены + `render_vray` с `save_path`.
- Копилка приёмов: кнопка «Запомнить приём», опрос параметров через
  `ask_user`, `save_recipe`/`get_recipe`, панель в шапке, обязательное
  применение подходящего приёма.
- Ограничитель расхода за ход (`TURN_TOKEN_BUDGET`, 400k) с вопросом
  «продолжать?» — пока Claude.
- Шапка: имя файла, переключатель темы (светлая — заглушка до дизайна),
  палитра из 10 цветов окна, свой цвет у каждой модели.
- Черновик инструкции: `docs/USER-GUIDE.md`; план и долгий ящик:
  `docs/ROADMAP.md`.

### V-Ray и защита от нативных плагинов (2026-09-14)

- Инструмент `render_vray`: рендер текущего вида в V-Ray через официальный
  Ruby API (размер, пресет качества, фоновое ожидание по событию,
  картинка в чат и модели, откат настроек). Проверено на V-Ray 6.20.
- `execute_ruby` отклоняет код с `VRay::`/`Enscape`: ошибка в нативном
  плагине роняет SketchUp целиком (так и вылетел 2026-09-13 — чтение
  параметра V-Ray строковым ключом). Промпт запрещает исследовать чужие
  API перебором.
- Плагин сообщает gateway, какие рендереры установлены (`renderers`).
- База знаний по проверенным вызовам: `docs/KNOWLEDGE-VRAY.md`. Enscape:
  Ruby API нет, только запуск через команду меню.

### Вопросы от модели (2026-09-13)

- `ask_user` задаёт все уточняющие вопросы одним вызовом: карточка с
  несколькими вопросами, у каждого варианты кнопками и поле «свой вариант»,
  одна кнопка «Ответить» отправляет всё одним сообщением.
- Промпт: перед первым изменением модели проверить габариты, место,
  количество, материал и спросить недостающее сразу, не по одному.
  Проверено: «сделай лестницу» → 5 вопросов, ответы кнопками и текстом,
  лестница построена по ответам за один ход.

### История (2026-09-13)

- Две кнопки в шапке: «Удалить историю» убирает переписку и сессии
  провайдеров в архив внутри файла модели (лента пустеет, модель начинает с
  чистого листа), «Восстановить историю» возвращает их; архив один, хранит
  последнюю удалённую переписку.

### Постпродакшн текущего ракурса (2026-09-12, Codex)

- Инструмент `render_viewport({prompt})`: пользователь выставил вид, попросил
  «сделай визуализацию» — в окне карточка «Зафиксировать и создать», после
  подтверждения кадр вьюпорта в исходном размере уходит во встроенную
  генерацию изображений Codex (`codex app-server`, вход по подписке ChatGPT)
  с ограничением сохранить ракурс, кадрирование и архитектуру.
- Результат показывается в чате с переключателем «Исходник / Результат» и
  сохранением PNG; картинки лежат в `%LOCALAPPDATA%/Stultus/renders`, в
  `.skp` — только id кадра и текст задания.
- Кнопка «Изменить» в карточке: задание правится прямо там перед
  генерацией, на генератор уходит текст пользователя.
- Миниатюра результата и исходника раскрывается по клику на всё окно,
  закрывается кликом или Esc.
- Под кадром показывается задание, по которому он сделан (и после
  восстановления из файла модели).
- Генератору жёстко запрещено менять ракурс, дистанцию, кадрирование и
  масштаб; то же правило — в системной подсказке для текста задания.
- Размышления модели идут в ленту свёрнутыми строками (Claude — сводка
  thinking, Codex — reasoning); сводка от API приходит по-английски.
- Включается на gateway: `RENDER_ENABLED=1` после `codex login`. Подробно —
  `docs/POSTPRODUCTION.md`.
- Проверено сквозь на виртуалке: из живого кадра 1615×883 получен PNG с
  сохранённым ракурсом; 7 серверных тестов (`npm test`), 4 Ruby-теста.

### Gateway

- Node-сервис: WebSocket для окон, per-окно MCP-сервер (Streamable HTTP,
  bearer-пропуск), провайдеры Claude (Claude Agent SDK) и Codex
  (@openai/codex-sdk), общая системная подсказка (для Codex — AGENTS.md в
  рабочем каталоге), Docker Compose для виртуалки.
- Прогон на живом SketchUp 2024 с Codex: ход проходит цикл сцена → код →
  проверка. Найдено и исправлено: Codex при `approvalPolicy: never`
  отклонял `execute_ruby` — нужен `default_tools_approval_mode = auto`.
